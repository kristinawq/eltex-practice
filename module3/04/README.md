# Производитель-потребители: семафор + разделяемая память System V

## Сборка и запуск

```bash
make          # собрать ./prodcons
make test     # собрать и запустить Unity-тесты
make clean
```

Каждый процесс запускается в своём терминале. Первым запускается производитель, он
создаёт память и семафор:

```bash
./prodcons producer [размер_памяти]   # в байтах, от 64 до 65536, по умолчанию 1024
./prodcons consumer                   # можно запустить несколько
./prodcons clean                      # удалить память и семафор
```

Пример вывода потребителя:

```
[consumer 163] набор: 62 94 32 8 42 -25 94 | max=94 min=-25
```

## Алгоритм работы

### Устройство разделяемой памяти


Заголовок `PcHeader`:
- `first` смещение первого блока (0 - блоков ещё нет);
- `last` смещение последнего блока, чтобы добавлять в конец без обхода списка;
- `end` смещение первого свободного байта;
- `finished` 1, когда производитель закончил запись.

Блок `PcBlock`: `count` - число элементов, `next` - адрес следующего блока, `values[]` -
сами числа. Блоки разной длины лежат подряд.

`count == 0` означает «набор обработан». Блок при этом остаётся в списке, чтобы цепочка
`next` не рвалась.

### Семафор

Один бинарный семафор: 1 - память свободна, 0 - занята. Начальное значение 1.

```c
struct sembuf lock = {0, -1, 0};
struct sembuf unlock[2] = {{0, 0, 0}, {0, 1, 0}};

semop(sem_id, &lock, 1);    /* занять: дождаться 1 и уменьшить до 0 */
semop(sem_id, unlock, 2);   /* освободить: дождаться 0 и увеличить до 1 */
```

Две операции `unlock` выполняются атомарно. Первая ждёт, пока семафор станет 0, вторая
увеличивает его до 1. Поэтому значение никогда не превысит 1: освобождение уже
свободного семафора не увеличило бы его, а заблокировалось.

Все обращения к списку (добавление блока, поиск необработанного набора, пометка
`count = 0`) выполняются между `lock` и `unlock`, поэтому два потребителя не могут забрать
один и тот же набор. Если `semop` прерван сигналом (`EINTR`), вызов повторяется.

### Производитель

1. `pc_create`: `shmget` с `IPC_EXCL` → `shmat` → заполнение заголовка → `semget` с
   `IPC_EXCL` → `semctl(SETVAL, 1)`. Семафор создаётся последним, поэтому потребитель не
   увидит память с неготовым заголовком.
2. Пока память не исчерпана: генерирует от 1 до 16 случайных чисел, записывает набор
   (`pc_put`), печатает его и «засыпает» на 0,3 с. Если очередной набор не поместился
   (`PC_FULL`), генерация заканчивается.
3. `pc_finish` ставит в заголовке `finished = 1`: потребители знают, что новых наборов не будет.
4. Пока `pc_unprocessed` возвращает больше нуля, производитель засыпает на 0,5 с и
   проверяет снова.
5. `pc_close(destroy)`: `shmdt`, затем `shmctl(IPC_RMID)` и `semctl(IPC_RMID)`.

### Потребитель

1. `pc_open`: `ftok` → `shmget` и `semget` без создания → `shmat`.
2. В цикле вызывает `pc_take`. Внутри, под блокировкой, она проходит по списку, находит
   первый набор с `count > 0`, копирует числа и ставит `count = 0`.
3. По полученным числам `main` находит максимум и минимум и печатает их.
4. После каждого шага засыпает на 0,7 с, в том числе когда необработанных наборов пока нет.
5. Завершается, когда `pc_take` вернул `PC_FINISHED` (производитель закончил, а
   необработанных наборов нет). Если производитель уже удалил семафор, `semop` вернёт
   `EINVAL` или `EIDRM`: это тоже нормальное завершение. Затем `shmdt`.
