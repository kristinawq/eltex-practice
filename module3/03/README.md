# P2P-чат на очередях сообщений POSIX + сигналы

## Задание

Написать программу, использующую две очереди сообщений для двустороннего
асинхронного взаимодействия

- При запуске указывается имя очереди сообщений. К нему добавляется `_1` для первой
  очереди и `_2` для второй.
- Если очередей с такими именами ещё нет, процесс создаёт их, через первую очередь
  принимает сообщения, а через вторую отправляет.
- Если очереди уже существуют, первая используется для отправки, а вторая для приёма.
- Для завершения обмена отправляется сообщение с заранее известным приоритетом,
  чтобы уведомить вторую сторону об окончании работы.
- Процесс, создавший очереди, удаляет их.
- При получении сигнала `SIGINT` отправляется сообщение об окончании работы.

## Сборка и запуск

```bash
make            # собрать ./p2p_chat
make test       # собрать и запустить Unity-тесты
make clean
```

Запуск в двух терминалах с одним и тем же именем:

```bash
./p2p_chat room       # терминал 1: создаст /room_1 и /room_2
./p2p_chat room       # терминал 2: подключится к ним
```

Набранная строка уходит собеседнику по Enter. Выход: команда `exit`, `Ctrl+D`
или `Ctrl+C`. Собеседник увидит `[собеседник завершил чат]` и тоже завершится.

## Алгоритм работы

### Роли и очереди

`chat_open` пытается создать `/name_1` с флагами `O_CREAT | O_EXCL`:

1. **Успех**: процесс становится создателем. Он создаёт `/name_2`, читает из `_1`,
   пишет в `_2` и запоминает `owner = 1`.
2. **`EEXIST`**: очередь уже есть, процесс подключается. Он пишет в `_1` и читает из `_2`.

Флаг `O_EXCL` объединяет проверку «очереди ещё нет» и создание в одну атомарную
операцию, поэтому два одновременно запущенных процесса не могут оба стать создателями.

Создатель делает `_2` сразу после `_1`. Подключающийся процесс, если `_2` ещё не
появилась (`ENOENT`), повторяет попытку открытия до 50 раз с паузой 0,1 с.

### Асинхронность

Программа двухпоточная:

- основной поток читает клавиатуру и отправляет сообщения;
- поток приёма блокируется в `mq_receive` и печатает входящее.

Благодаря этому сообщения собеседника появляются в любой момент, независимо от
того, печатает ли пользователь.

Основной поток ждёт ввод через `poll()` с таймаутом 100 мс, чтобы регулярно проверять
два флага: «нажали Ctrl+C» и «собеседник завершил работу».

### Завершение обмена

Уведомление о завершении - это сообщение с приоритетом `CHAT_PRIO_QUIT = 10`
(обычные сообщения идут с приоритетом 1). Получатель определяет тип сообщения по
приоритету, который возвращает `mq_receive`.

Завершение инициируется тремя способами: командой `exit`, концом ввода (`Ctrl+D`)
и сигналом `SIGINT`. Во всех случаях выполняется одна и та же последовательность:

1. основной поток выходит из цикла ввода;
2. если собеседник ещё не завершился, ему отправляется сообщение с приоритетом `CHAT_PRIO_QUIT`;
3. поток приёма отменяется (`pthread_cancel`) и присоединяется (`pthread_join`);
4. `chat_close` закрывает очереди; создатель дополнительно вызывает `mq_unlink`
   для обеих очередей.

Если уведомление пришло от собеседника, поток приёма сам заканчивает работу и
выставляет атомарный флаг. Основной поток замечает его и завершается без повторной
отправки уведомления.

### Обработка SIGINT

Обработчик сигнала (`sigaction`) только выставляет флаг `sigint_received`: в обработчике
нельзя делать ничего сложного. Уведомление отправляет основной поток, заметив флаг при
очередной проверке. Обработчик установлен без `SA_RESTART`, поэтому
прерванный сигналом `mq_receive` возвращает `EINTR`, и поток приёма просто повторяет вызов.

## Особенности реализации

- **Имя очереди.** Если имя не начинается с `/`, оно добавляется автоматически.
  Пустое или слишком длинное имя - ошибка `EINVAL`.
- **Приоритет и порядок.** Очередь POSIX отдаёт сообщения в порядке убывания приоритета,
  поэтому уведомление о завершении обгоняет ещё не прочитанные обычные сообщения.
- **Размер сообщения.** До 255 символов (`CHAT_MSG_SIZE = 256` вместе с `\0`), в очереди
  помещается до 10 сообщений. Более длинная строка отправляется несколькими сообщениями.
- **Полная очередь.** Отправка использует `mq_timedsend` с таймаутом 1 с, чтобы программа
  не зависала навсегда, если собеседник ничего не читает. По таймауту выводится ошибка
  `ETIMEDOUT`, и чат завершается.
- **Буфер приёма** всегда на 1 байт больше сообщения, поэтому строка гарантированно
  завершается `\0`.

## Тесты

Unity-тесты проверяют библиотеку в одном процессе: создатель и
подключившийся - два экземпляра `chat_t`.

- роли (создатель или подключившийся) и формирование имён очередей;
- передача сообщений в обе стороны, независимость направлений, сохранение порядка;
- приоритет уведомления о завершении: оно приходит раньше обычных сообщений;
- предельный размер сообщения, слишком длинное сообщение;
- переполнение очереди;
- очереди удаляет только создатель;
- некорректные имена.
