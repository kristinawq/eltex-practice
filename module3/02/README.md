# Задание 2: Издатель - Брокер - Подписчик

## Описание задачи
Программа реализует модель обмена сообщениями. Один процесс выступает в роли центрального узла (Брокера), который принимает сообщения от издателей и отправляет их подписчикам в зависимости от выбранных тем.

Программа запускается с одним из трех флагов:
- **`-b`**: Запуск брокера (создает очередь сообщений).
- **`-p <тема>`**: Запуск издателя (отправляет сообщения в указанную тему).
- **`-s <тема1> <тема2>...`**: Запуск подписчика (слушает указанные темы).

## Архитектура

В основе программы лежат очереди сообщений System V (`msgget`, `msgsnd`, `msgrcv`) и сигналы (`signal`, `kill`).

### Роли процессов:

1. **Брокер**
   - Создает очередь сообщений с уникальным ключом (`MSG_KEY = 12345`). Использует флаг `IPC_EXCL`, чтобы предотвратить запуск второго брокера.
   - Запускает бесконечный цикл чтения `msgrcv` с приоритетом 1.
   - Хранит в памяти массив подписчиков и издателей.
   - Обрабатывает команды из сообщений: `subscribe` (добавить в список), `unsubscribe` (удалить из списка), `send` (переслать подписчикам).
   - При получении `SIGINT` (Ctrl+C) рассылает сигналы всем известным процессам и удаляет очередь.

2. **Издатель**
   - Формирует строку send,<PID>,<тема>.
   - Отправляет её в очередь с приоритетом 1, чтобы брокер прочитал.
   - Делает 5 итераций и завершается.

3. **Подписчик**
   - Отправляет Брокеру сообщения subscribe,<PID>,<тема> для каждой указанной темы.
   - Ждет сообщения из очереди с приоритетом, равным своему PID.
   - При получении `SIGINT` отправляет unsubscribe,<PID>,<тема> и завершается.

### Приоритеты сообщений
Очередь одна для всех процессов. Чтобы процессы не путали сообщения, используется поле `mtype`:
- **Тип 1**: Служебные сообщения (от подписчиков/издателей к брокеру).
- **Тип = PID**: Сообщения данных (от брокера к конкретному подписчику). Благодаря этому подписчик читает только те сообщения, которые предназначены лично ему.

## Взаимодействие

1. Пользователь запускает **Брокера**. Очередь создана, брокер ждет сообщения с типом 1.
2. Пользователь запускает **Подписчика**. Он отправляет `subscribe,1234,weather`. Брокер читает, записывает PID 1234 в базу.
3. Пользователь запускает **Издателя**. Он отправляет `send,5678,weather`.
4. Брокер читает это сообщение, видит, что тема weather интересна подписчику 1234, и отправляет ему данные с типом 1234.
5. Подписчик забирает сообщение и выводит его на экран.
6. При нажатии Ctrl+C на брокере, он посылает `SIGINT` всем. Подписчик отписывается, очередь удаляется.
